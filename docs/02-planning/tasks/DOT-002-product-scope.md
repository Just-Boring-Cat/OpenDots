# DOT-002 Confirm Product Identity And First Workflow

## Summary

Turn the owner's product vision into a testable initial product definition
without narrowing the long-term assistant vision prematurely.

## Acceptance Criteria

- [ ] Choose a working name or explicitly keep OpenDots through the prototype.
- [ ] Choose one first workflow and identify the user, inputs, tools, outputs,
  approval points, and failure behavior.
- [ ] Define success measures and what must be observable in a manual test.
- [ ] Separate the first prototype scope from later personal assistant and
  commercial-product ambitions.
- [ ] Update product requirements and roadmap after owner review.

## Open Questions

- Which task should the first Dot perform end to end?
- Should the first test run on the owner's computer, a private server, or both?
- Which actions may be automated, and which must remain draft-and-confirm?
